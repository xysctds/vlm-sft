# DeepFashion 部署说明

> 本文档记录「Qwen3-VL-8B 服装属性抽取 LoRA 微调」模型的服务化部署全流程：环境准备、vLLM 启动、CLI/Gradio 两种 demo 验证方式，以及部署过程中踩过的坑（换机复现时直接照做即可）。

## 1. 前置产物

| 项 | 路径 | 说明 |
|---|---|---|
| merged 模型 | `llamafactory/saves/dfattr/merged/qwen3vl8b_dfattr_merged/` | LoRA adapter 已合并，17G（4 个 safetensors + tokenizer + config） |
| 客户端脚本 | `scripts/serve_demo.py` | CLI demo（vLLM OpenAI 兼容接口） |
| Web 页面 | `scripts/serve_gradio.py` | Gradio 浏览器 demo |

## 2. 环境准备

部署用**独立 conda 环境 `vllm`**（克隆自训练环境 `lf`，避免污染训练环境）：

```bash
# 1) 克隆 lf 环境（conda 硬链接，几乎不占额外磁盘）
conda create -n vllm --clone lf -y

# 2) 安装 vllm（vllm 0.27.1 与 lf 的 torch 2.13.0+cu130 版本匹配，不会改动 torch）
conda activate vllm
pip install vllm

# 3) 升级 flashinfer（0.6.16.post3 有 array.array 注解 bug，见 §6.1）
pip install -U flashinfer-python
```

## 3. 启动 vLLM 服务

**注意**：必须在仓库根目录运行（模型路径为相对路径），且需显式设置 `CUDA_HOME`（vllm 编译内核需要 nvcc，见 §6.3）。

```bash
conda activate vllm
export CUDA_HOME=/home/maotai/.conda/envs/vllm/lib/python3.11/site-packages/nvidia/cu13

# —— 单卡（默认，48G 单卡即可）——
vllm serve llamafactory/saves/dfattr/merged/qwen3vl8b_dfattr_merged \
    --served-model-name deepfashion \
    --port 8000 \
    --gpu-memory-utilization 0.9 \
    --max-model-len 32768

# —— 多卡：TP=2 + 128k 长上下文（2 卡，KV cache 约 2.7 倍）——
vllm serve llamafactory/saves/dfattr/merged/qwen3vl8b_dfattr_merged \
    --served-model-name deepfashion \
    --port 8000 \
    --gpu-memory-utilization 0.55 \
    --max-model-len 131072 \
    --tensor-parallel-size 2

# 后台启动（日志写 llamafactory/results/vllm_serve.log）
VLLM_USE_FLASHINFER_SAMPLER=0 nohup vllm serve ... > llamafactory/results/vllm_serve.log 2>&1 &
```

> **TP 数上限**：Qwen3-VL-8B 有 32 个注意力头（GQA 8 个 KV head），`--tensor-parallel-size` 必须整除 head 数（可取 1 / 2 / 4 / 8），**3 不可用**（见 §6.5）。3 卡环境只能 TP=2，第 3 张卡可另起服务或留作它用。

**关键参数说明**：

| 参数 | 值 | 原因 |
|---|---|---|
| `--served-model-name deepfashion` | demo 客户端请求的模型名 | 与 `serve_demo.py` / `serve_gradio.py` 默认值对应 |
| `--max-model-len 32768` | 32k（单卡） | 模型默认 max_seq_len=262144，KV cache 需 36GiB 超出单卡余量；单图+短输出 32k 绰绰有余（见 §6.2）。多卡 TP=2 可提到 131072 |
| `--tensor-parallel-size 2` | 2（多卡） | 权重摊到 2 卡，KV cache 总量约 2.7 倍，支持 128k 上下文（见 §6.5） |
| `--gpu-memory-utilization 0.55` | 55% | 48G 卡：权重 ~9G + KV cache ~15.5G/卡；**0.9 会预分配 90% 显存（每卡 44G），改 0.55 每卡省 ~17G**，仍够 128k 上下文（并发 1.7x）。省显存给其他任务时调低即可 |
| `VLLM_USE_FLASHINFER_SAMPLER=0` | 禁用 flashinfer 采样器 | flashinfer JIT 编译与 nvcc 13 头文件不兼容（见 §6.4） |

**启动成功标志**：日志出现 `Application startup complete`，且 `ss -tlnp | grep 8000` 有监听。

## 4. 验证 demo（CLI）

另开终端，传一张没见过的图（如 test 集图片）：

```bash
conda activate vllm   # 或任意有 requests 的环境
python scripts/serve_demo.py --image /path/to/never_seen.jpg
```

输出模型原始 JSON 与解析后的结构化属性。验证通过后，可继续对外提供 OpenAI 兼容接口（`http://localhost:8000/v1`）。

### 4.1 OpenAI 兼容 API 调用示例

服务暴露标准 OpenAI 兼容接口（`/v1/chat/completions`，vLLM 实现），任何 OpenAI SDK / HTTP 客户端可直接对接：

```bash
# curl 示例（图片 base64 → 结构化属性 JSON）
IMG_B64=$(base64 -w0 /path/to/never_seen.jpg)
PROMPT='Extract the clothing attributes visible in this image and output a JSON object.'
curl -s http://localhost:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d "{
    \"model\": \"deepfashion\",
    \"messages\": [{\"role\": \"user\", \"content\": [
      {\"type\": \"image_url\", \"image_url\": {\"url\": \"data:image/jpeg;base64,${IMG_B64}\"}},
      {\"type\": \"text\", \"text\": \"${PROMPT}\"}
    ]}],
    \"max_tokens\": 512,
    \"temperature\": 0.0
  }"
```

```python
# Python 示例（openai SDK）
from openai import OpenAI

client = OpenAI(base_url="http://localhost:8000/v1", api_key="EMPTY")
resp = client.chat.completions.create(
    model="deepfashion",
    messages=[{"role": "user", "content": [
        {"type": "image_url", "image_url": {"url": f"data:image/jpeg;base64,{b64}"}},
        {"type": "text", "text": PROMPT},
    ]}],
    max_tokens=512, temperature=0.0,
)
print(resp.choices[0].message.content)  # 结构化属性 JSON
```

> 注意：请求中的 `model` 必须与服务启动时的 `--served-model-name` 一致（此处为 `deepfashion`）；`temperature=0` 保证输出确定性。

## 5. Web 页面（Gradio，可选）

**注意**：页面脚本跑在 **lf 环境**（vllm 环境里 vllm 装的 starlette 1.6 与 gradio 5.50 冲突，lf 环境两者兼容；页面只是 HTTP 客户端，不需要 vllm 包）。

```bash
conda activate lf
python scripts/serve_gradio.py            # 日志写 llamafactory/results/gradio.log
# 浏览器打开 http://127.0.0.1:7860
```

**页面功能**（`serve_gradio.py`）：

| 功能 | 说明 |
|---|---|
| 图片上传 | 固定 300px 等比显示，点开看全图 |
| Prompt 模板切换 | `schema` / `simple` 单选，切换后自动填入编辑框 |
| Prompt 手动编辑 | 编辑框在图片下方，可直接改模板或写自定义 prompt（如中文描述要求） |
| 抽取属性 | 左侧点按钮，右侧显示「模型原始输出」+「解析后的结构化属性」（全量展示无滚动） |

页面只做展示层，请求逻辑与 CLI 一致（图片 base64 + prompt + temperature=0），无独立计算。

## 6. 踩坑记录

### 6.1 flashinfer 0.6.16.post3 的 array.array 注解 bug
- **现象**：vllm 启动即崩，`TypeError: type 'array.array' is not subscriptable`（`flashinfer/comm/fd_exchange.py`）。
- **原因**：0.6.16.post3 的 `fd_exchange.py` 用了 `array.array[int]` 类型注解，当前 Python 3.11 环境不支持。
- **解决**：`pip install -U flashinfer-python`（升到 0.6.17 修复）。

### 6.2 max_seq_len 过大导致 KV cache 显存不足
- **现象**：`ValueError: To serve at least one request with the model's max seq len (262144), 36.0 GiB KV cache is needed ...`
- **原因**：Qwen3-VL 的 max_position_embeddings=262144，vllm 默认按此分配 KV cache。
- **解决**：`--max-model-len 32768`（对本任务足够）。

### 6.3 找不到 nvcc / CUDA_HOME
- **现象**：`RuntimeError: Could not find nvcc and default cuda_home='/usr/local/cuda' doesn't exist`。
- **原因**：机器没有系统 CUDA，nvcc 来自 pip 的 cuda-toolkit 包。
- **解决**：`export CUDA_HOME=<conda-env>/lib/python3.11/site-packages/nvidia/cu13`（nvcc 所在目录的上级）。

### 6.4 flashinfer JIT 编译与 nvcc 13 头文件不兼容
- **现象**：`ninja ... returned non-zero exit status 1`，编译报 `cuda_toolkit.h: #error "CUDA compiler and CUDA toolkit headers are incompatible"`。
- **原因**：flashinfer 自带 cccl/libcudacxx 头文件与 nvcc 13.0 不匹配。
- **解决**：`VLLM_USE_FLASHINFER_SAMPLER=0` 禁用 flashinfer 采样器（单卡 8B 无性能影响）。

### 6.5 张量并行数受注意力头整除约束（TP=3 不可用）
- **现象**：`ValueError: Total number of attention heads (32) must be divisible by tensor parallel size (3)`。
- **原因**：TP 会把注意力头均分到各卡，head 数必须能被 TP 整除；Qwen3-VL-8B 为 32 头 / 8 KV 头，只能取 1/2/4/8。
- **解决**：3 卡环境用 `--tensor-parallel-size 2`（第 3 张卡另作他用），或换支持 TP=3 的模型。

## 7. 停止 / 重启

```bash
# 停止 vLLM（8000 端口）
pgrep -af "[v]llm serve" | awk '{print $1}' | xargs -r kill

# 停止 Gradio（7860 端口）
pgrep -af "[s]erve_gradio" | awk '{print $1}' | xargs -r kill

# 重启：按 §3 / §5 命令重新执行即可
```

> 方括号写法（`[v]llm` / `[s]erve_gradio`）是为了避免 kill 命令匹配到自己的命令行（`pkill -f "vllm serve"` 会误杀执行该命令的 shell 自身）。
