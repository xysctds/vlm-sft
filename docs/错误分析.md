# 错误分析（诊断与干预实证）

对 Qwen3-VL-8B 主模型（属性级准确率 93.4%、全 JSON 匹配率 45.8%）做一轮针对错误样本的诊断与干预实证：先按样本维度定位错误结构，再实测三条低成本干预路线，用负结果收敛「什么可修、什么不可修」。

- 评测口径：val 全量 4,410 条，LoRA 最终主模型（`experiments/qwen3vl8b/main/reports/preds_val_lora.jsonl`）；指标定义见主文档 §5.1，本文不重复定义
- 与主文档的分工：属性维度的错误分布与归因已在主文档 §7；本文只补样本维度诊断与三条干预路线的实证，不改动 §7、原数据与主模型权重
- 数值来源：§2 的计数由 `experiments/qwen3vl8b/badcase_study/scripts/analyze_badcase_*.py` 输出（脚本未落盘，本文即记录）；§3.1 的表摘录自同目录 `reports/report_hardcase_retrain_vs_main_val.md`
- 实验代码、配置与产物在 `experiments/qwen3vl8b/badcase_study/`，复跑方式见该目录 `README.md`

## 摘要

三条路线的实测结果：

| 路线 | 结果 |
|---|---|
| 诊断（样本维度） | 全 JSON 匹配率被 1320 个「只错 1 个属性」的样本卡死，错误高度稀疏 |
| 难例续训 `hardcase_retrain` | 负结果：全 JSON 匹配率 44.4% < 45.8%，排除「难例数据不足」假设 |
| 约束解码 / 后处理 | 实测救回 0 个全 JSON 匹配样本，排除「推理端可修」假设 |

剩余错误主体是视觉本质难例与可见性判断。低成本手段（数据增强 / 改 prompt / 后处理）经实证均无法突破，可能有效的方向只有解冻视觉塔或换更强视觉能力的基座，成本较高（见 §5）。

## 1. 背景：为什么要从样本维度看

主文档 §7 已给出属性维度的错误分布（哪个属性错得多、哪些混淆对）。本文补充样本维度——每个样本错几个、错在漏键 / 多键 / 错值——据此判断「什么能低成本修、什么不能」。

评测纪律按主文档 §5.3：预测走 llamafactory 管线、`eval_attr.py` 打分。任何推理端改动（约束解码、评测后处理）都必须与训练同口径，否则不可比；这条直接决定了 §3.2 的结论能否成立。

## 2. 诊断：错误样本的结构

### 2.1 错误规模分布（样本级）

4,410 条中有 2,391 条未达全 JSON 匹配。按每个失败样本的错误属性数拆分：

| 单样本错误数 | 失败样本数 | 占失败样本 | 若全部修好后的全 JSON 匹配率 |
|---|---|---|---|
| 1 | 1320 | 55% | 75.7% |
| 2 | 591 | 25% | 89.1% |
| 3 | 270 | 11% | 95.2% |
| ≥4 | 210 | 9% | >95% |

错误高度稀疏：约八成失败样本只错 1~2 个属性。全 JSON 匹配率是被大量微小局部错误卡死的，不是系统性错乱。

### 2.2 只错 1 处的 1320 个样本

| 类型 | 数量 | 含义 |
|---|---|---|
| 同键错 1 值 | 919 | 键两边都在、取值不同，以视觉细粒度混淆为主 |
| 多输出 1 个键 | 278 | 模型输出了真值里没有的键，即可见性幻觉 |
| 漏 1 个键 | 123 | 真值有、模型没输出，即小物件 / 存在性漏检 |

三点观察：

1. 同键错值是主体（919），集中在 `lower_fabric` / `upper_fabric` / `upper_pattern` / `lower_pattern` / `neckline` / `ring` / `sleeve_length`，即面料与图案的视觉细粒度、领型、小物件。
2. 多键（278）比漏键（123）多一倍，说明模型存在可见性幻觉——输出了真值中被剔除的键（不可见 / NA / hidden）。全部失败样本中多输出的键 top：`neckline`(179)、`neckwear`(168)、`outer_clothing_is_cardigan`(155)、`waist_accessories`(138)、`ring`(94)。
3. 单错样本里的多输出集中在 `neckline`(58) / `waist_accessories`(49) / `neckwear`(46) / `ring`(27)，是结构性的存在性抑制缺陷，非随机。

### 2.3 归因：什么可修、什么不可修

| 错误族 | 单错里数量 | 能否低成本修 | 依据 |
|---|---|---|---|
| texture 同键错值（chiffon↔cotton、denim↔cotton、graphic↔pure color） | ~400+ | 难 | train 中 cotton 2.78 万条、pure color 2.7 万条，样本已海量仍双向混淆，属视觉边界本质难例，不是数据量问题 |
| 领型 / 袖长细粒度边界（V↔round、medium↔long） | ~180 | 中 | 同上，视觉细粒度 |
| 小物件 yes↔no（ring / neckwear / wrist / waist） | ~180 | 中 | 目标小且常被遮挡，视觉受限 |
| 多 / 漏键（可见性抑制） | 401 | 理论较高 | 结构性的「该省略却输出 / 该输出却省略」 |

## 3. 干预实证

### 3.1 难例续训（`hardcase_retrain`）：负结果

做法：在现役最终 LoRA adapter 上，用难例增强训练集（7,844 条，含长尾稀有类、结构性存在性属性、小物件）以 3e-5 低 lr 续训 2 epoch（436 步，等效 batch 36），train_loss 降至 0.018。评测沿用原 val 与原 schema prompt，与主模型同口径。

| 模型 | 全 JSON 匹配率 | 属性级准确率 | macro-F1 |
|---|---|---|---|
| 主模型 | 45.8% | 93.4% | 0.670 |
| 难例续训后 | 44.4% | 92.6% | 0.661 |

（上表为摘录；完整逐属性表与 McNemar 检验见 `experiments/qwen3vl8b/badcase_study/reports/report_hardcase_retrain_vs_main_val.md`）

逐属性看多数轻微下降，其中 glasses / hat / neckline / neckwear / sleeve_length 显著变差（McNemar p<0.001）。

三点方法论意义：

1. 排除「难例数据不足」假设。主模型已在全量 35k 上收敛，再补难例只会带来轻微过拟合与遗忘。
2. 印证 §2.3：剩余错误是视觉本质难例，补数据无法突破。
3. 这是对主文档 §7.3「补困难样本 / 类别加权」的实证检验——数据已覆盖充分时，该方向无增益。

### 3.2 约束解码 / 后处理：实测救回 0 个

针对多 / 漏键能否用约束解码或后处理修复，做了定量验证（`constraint_analysis.py`）：

| 失败样本错误类型 | 样本数 | 约束解码能否救 |
|---|---|---|
| 仅同键错值（视觉） | 1286 | 否，值都合法 |
| 多键 | 381 | 否，真值已剔除 NA，不知该省略哪个键 |
| 漏键 | 177 | 否，不知该补哪个键 |
| 组合 | 456 | 否 |

结论：失败样本中「仅格式层错误（非法值 / 漂移键）、修好即全 JSON 匹配」的有 0 个（0.0%）。原因有两条：一是输出 parse 率已是 100%，无非法值与漂移键，格式层本就干净；二是剩余错误全是同键错值（视觉）与多 / 漏键（可见性判断），约束解码只能保证输出合法 schema，既不知道该省略或补哪个键，也修不了视觉判错的值。

### 3.3 强化 prompt 重训（`prompt_retrain`）：未跑完

强化可见性 prompt 版数据与配置已备好，在 GPU 1,2 上启动 2 卡训练。该路线需约 14.5h，且强化 prompt 存在 NA 语义矛盾风险（原数据里「没戴 → no」与「看不到 → NA 省略」必须区分，改 prompt 有口径漂移风险），训练到 190/2514 步被停，无有效模型。若要继续，需先修正 prompt 的 NA 语义再重跑。

## 4. 结论

两个负结果把可试的方向收窄成三类：

| 方向 | 判断 |
|---|---|
| 数据增强（补难例） | 不通，难例续训实证为负 |
| 改 prompt / 后处理 / 约束解码 | 不通，约束解码实测救回 0 |
| 解冻视觉塔 / 换更强视觉基座 | 唯一可能有实质提升的方向；同键错值的根因是视觉判别，数据侧与推理侧都够不着 |

## 5. 后续选项

| 选项 | 说明 | 成本 / 风险 |
|---|---|---|
| A. 就此收手 | 两个负结果已把数据侧与推理侧方向双双闭环 | 无额外成本 |
| B. 解冻视觉塔小步探针 | 先用小数据 / 短训练验证是否有提升，再决定是否放大 | 中等；方向最可能有效 |
| C. 继续 `prompt_retrain` | 强化可见性 prompt 后从基座全量重训 | 约 14.5h；需先修 NA 语义；新口径不与旧口径直接可比 |
