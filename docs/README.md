## 相互关系

- **`技术报告` / `项目方案`**：一份是「结果」，一份是「规划」，互补不互斥。`项目方案` 刻意自包含（§5.2/§6.2/§9.1 内嵌属性表、schema prompt、评测指标），供独立阅读与投递；`技术报告` 是完成后沉淀的结果叙事。
- **`检索推荐方案`** 是 `项目方案` 主线 demo（图→属性 JSON）的**延伸**：把抽取结果的终点变成相似款检索的起点，复用同一视觉塔与数据。其 Gradio 集成已体现在 `部署说明` §5/§6.6。
- **运维三件套（数据/部署/调参）** 是被两份主文档和方案所引用的操作手册：主文档只给出命令与链接，具体环境/踩坑细节下沉到这三份。属性对照表是 `数据说明` 的附录（唯一权威属性来源，见下方说明）。

## 属性表权威来源约定

> 18 维属性体系的**唯一权威来源**是 `数据说明.md` 的「附录：属性对照表（英中）」（由官方 README + `scripts/data_convert_deepfashion_multi.py` 内嵌表整理）。为避免三处重复导致口径漂移，**新增/改动属性只改这里**；`技术报告`/`项目方案` 因要求自包含，各自保留一份内嵌副本（如需同步，以本附录为准）。

## 修改约定

- 改文档前先 `read`；
- 两份主文档因自包含约束，允许保留内嵌副本；
- 运维参考新增内容优先落在对应三份手册里，而不是塞进主文档。
