# 检索 / 推荐技术方案（图 → 属性 → 相似款检索）

> **定位**：把主线 demo（图 → 结构化属性 JSON）的终点变成起点——用抽出的 18 维属性 + 视觉特征，在 DeepFashion-MultiModal 全库（约 4.4 万图 / 7975 件商品，入索引 7972 件）里检索最相似的「相似款」，让 demo 升级成「电商标注 + 相似款推荐」完整场景。
>
> **实现**：**属性 + 视觉向量混合检索**。用冻结的 Qwen3-VL 视觉塔（`model.visual`）抽库内图 embedding 走向量检索，叠加官方标注的属性约束做过滤/加权。

---

## 1. 方案概述

混合检索由三条互补信息决定相似度：

| 维度 | 来源 | 作用 |
|---|---|---|
| 视觉特征 | 冻结 Qwen3-VL 视觉塔抽库内图 embedding | 视觉形态相似 |
| 属性语义 | 查询 JSON 与库内官方属性真值匹配 | 语义可控（面料/图案/款式） |
| 同款排重 | 商品 id 聚合 | 避免同一款重复刷屏 |

复用现有 `model.visual` 与现有数据，零新增标注、不动训练；属性约束作为检索的可控维度，检索结果可信、可复用，且天然能做「官方标注 vs 模型抽取」的可视对照。

## 2. 数据基础（全部现成，零新增标注）

| 数据 | 位置 | 用途 |
|---|---|---|
| 图片 44,096 张 | `data/data_convert/deepfashion_multi/images/` | 抽视觉 embedding 的图库 |
| 形状标注 `shape_anno_all.txt` | `.../labels/shape/shape_anno_all.txt` | 12 维形状属性 id（检索约束，官方真值） |
| 纹理标注 `fabric_ann.txt` / `pattern_ann.txt` | `.../labels/texture/` | 上下外装面料 + 图案 id |
| 文本描述 `captions.json` | `data/data_convert/deepfashion_multi/` | 展示用 caption |
| 属性表 `SHAPE_ATTRS` / `FABRIC_VALS` / `PATTERN_VALS` | `scripts/data_convert_deepfashion_multi.py` | id → 语义映射 |

**关键点**：索引用**官方标注**（真值）而非模型抽取结果做检索约束，检索结果可信、可复用。

### 商品 id 聚合

文件名形如 `MEN-Denim-id_00000080-01_7_additional.jpg`：

```
<大类>-<小类>-id_<商品id>-<子序号>_<视角号>_<角度>.jpg
```

- **商品 id**：`id_00000080` 之后、`-NN` 之前的部分，即 `00000080`（全库共 **7975** 个唯一 id；其中 **7972** 个有 shape/caption 标注并已入索引，`00001283 / 00003020 / 00004485` 3 个商品共 9 张图无任何标注，建索引时被过滤）。
- 同一商品的多个视角/角度/子序号**聚合为一个检索条目**，检索返回时只保留一张代表图，避免同一款重复刷屏。

## 3. 检索管线

```
用户上传图 ──▶ 属性抽取 demo（已有）──▶ 属性 JSON
                                          │
                                          ▼
        ┌─────────────────────────────────────────────┐
        │  retrieval.py                                │
        │  1. 属性约束过滤：查询 JSON 与库内官方属性匹配 │
        │  2. 视觉相似：查询图 embedding 与库向量余弦     │
        │  3. 同款排重 + 加权合并                        │
        └─────────────────────────────────────────────┘
                                          │
                                          ▼
                              Gradio 相似款 Gallery（top-k）
```

### 3.1 视觉向量索引（离线，`build_retrieval_index.py`）

- 用**冻结的视觉塔**（`Qwen3-VL-8B-Instruct`，`model.visual`）对每张图抽 patch 特征。
- `vis(pixel_values, grid_thw=thw)` 返回 `.last_hidden_state`，形状 `[num_patches, 1152]`；`mean(dim=0)` 得 1152 维向量。
- 统一预处理：`image_processor.min_pixels=1024, max_pixels=825750`（与训练一致，不压缩细节）。
- 归一化后按商品聚合存 `index_vectors.npy`（7972×1152，行序与 meta 对应）+ `index_meta.json`（一个 list，长度 7972，每项含 id / 代表图 / 角度 / 属性）。
- 处理方式：只给**每个商品 id 选 1 张代表图**（优先 `1_front`，其次 `2_side`），避免 4.4 万张全抽、也避免同款重复。
- **多卡并行**：`--shard N --nshards M` 分片并行（每卡一段），`--merge` 合并为最终索引（已用 3×4090 构建全量 7972 件，约 10 分钟）。

### 3.2 属性约束（真值过滤/加权）

- 查询 JSON 中**可见**的键值（模型已剔除不可见项），与库内官方 `shape+fabric+pattern` 属性比较。
- 属性匹配分 `attr_score = 命中维度数 / 查询总维度数`，作为**软加权**：

```
final = w_vis * vis_cos + w_attr * attr_score
默认 w_vis = 0.7, w_attr = 0.3
```

- 亦可对属性分 < 阈值（如 0.5）的候选做**硬过滤**。

### 3.3 同款排重

检索结果里同一 `id_` 只保留 top 1 张（若全库向量模式则按 id 聚合后取最高分）。

## 4. 检索实现细节

### 4.1 只加载视觉塔

检索时用 `Qwen3VLVisionModel` 单独加载视觉塔（576M / 1.2GB），**跳过 8B 语言模型（17GB）**，避免每次检索重复加载整模型。

- 首次加载耗时从 ~48s 降到数秒。
- 实测独立视觉塔输出与建索引时完整模型 `model.visual` 完全一致（cosine=1.0）。

### 4.2 模型单例缓存 + 启动预热

- `embed_query` 用模块级单例缓存复用视觉塔，避免每次检索重复加载。
- `serve_gradio.py` 启动时后台 `preload_vision_tower()` 预热，用户首次点击即秒级出结果。
- 实测：首次检索 ~3.2s，缓存命中 ~0.2s。

### 4.3 向量检索

向量检索**不引入 faiss**，用 numpy 归一化点积即可（7972×1152 一次全量余弦毫秒级）；库变大可后续换 faiss。

## 5. 工程纪律

- **属性口径**：检索约束一律用官方 `SHAPE_ATTRS` / `FABRIC_VALS` / `PATTERN_VALS` 映射，与训练数据同源，避免口径漂移。
- **embedding 环境一致性（关键）**：查询 embedding 与索引 embedding 必须来自**同一个 conda 环境 / transformers 版本**，否则向量可能漂移。索引构建用 `lf`，查询在 `vllm`（与 lf 同 transformers 5.8），已验证 cosine=1.0 严格对齐。换版本需重测对齐。
- **GPU 分卡避让**：vLLM 服务与 Gradio 查询模型是不同进程，必须用 `CUDA_VISIBLE_DEVICES` 指定各自所在卡，避免同卡 OOM（本机 vLLM 占 GPU0，Gradio 查询模型放 GPU2）。
- **库内查询对照**：内置自检（取库中一张图的 embedding 当查询，应 top-1 命中自身）。
- 索引产物（`index_vectors.npy` / `index_meta.json`）与 `llamafactory/saves` 一致走 git 忽略，不入库。

## 6. 落地产物

| 文件 | 内容 |
|---|---|
| `scripts/build_retrieval_index.py` | 解析 `shape_anno_all.txt` + `fabric_ann.txt` + `pattern_ann.txt` + `captions.json` → 聚合成商品索引 → 用视觉塔抽 embedding → 存 `index_vectors.npy` + `index_meta.json`；支持 `--shard N --nshards M` 多卡分片并行 + `--merge` 合并 + 库内自检 |
| `scripts/retrieval.py` | 加载索引；输入（属性 JSON, 查询图 embedding）→ 属性过滤/加权 + 向量余弦 → 返回 top-k 商品（含代表图路径、属性、匹配分）。含 `RetrievalIndex` 检索类、`load_vision_tower` / `preload_vision_tower`（只加载视觉塔 + 预热）、`embed_query`（带模型单例缓存） |
| `scripts/serve_gradio.py` | 现有属性抽取基础上加「相似款」Gallery：点按钮后自动检索 top-k，相似图 + 匹配分（图上 caption 直接标注）；检索 embedding 复用 `retrieval.py`，模型单例缓存 + 启动预热 |
| `docs/检索推荐方案.md` | 本文档 |
