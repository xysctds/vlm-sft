# DeepFashion 服装属性微调 · 调参说明（精简版）

> 对应配置：`llamafactory/config/qwen3vl8b_dfattr_train_cli.yaml`
> 任务：服装图 → 18 维属性 JSON（`deepfashion_attr_json_train`，35,276 条，80/10/10 三划分的 train 侧；类别极不均衡）
> 模型/硬件：Qwen3-VL-8B-Instruct，**3×48GB 4090，CLI 提交训练时 LLaMA-Factory 自动 3 卡 DDP**
> 基线：`llamafactory/config/default.yaml`（CLI 默认）

---

## 一、相对默认值的改动（及原因）

| 参数 | 默认 | 最终 | 为什么改 |
|---|---|---|---|
| `lora_target` | `''` | **`all`** | **必修 bug**：空串解析为 `['']`，不匹配任何模块 → LoRA 完全不生效（源码证实）；`all` 为框架默认、自动挂全部线性层 |
| `learning_rate` | 5e-5 | **1e-4** | LoRA 冻结 99% 参数，需比全参 SFT 更大步长；35.3k 数据不会震荡，5e-5 偏保守 |
| `lora_rank` | 8 | **16** | 78 个键值模式 + 细粒度视觉判别（面料/图案/领型），r=8 表达容量偏紧 |
| `lora_alpha` | 16 | **32** | 保持 **α/r=2** 标准比例（改 rank 必须联动） |
| `lora_dropout` | 0 | **0.05** | 3 epoch 反复遍历 + 类别长尾（val 分布：glasses 的 no 3,759 vs sunglasses 72），低成本正则防过拟合 |
| `batch_size` | 2 | **4** | 每步吞吐更高；**注意**：不压缩（756×1092，1,053 视觉 token）+ 无梯度检查点下激活较高，先小步验证显存，OOM 则降回 2 |
| `gradient_accumulation_steps` | 8 | **3** | **3 卡 DDP 下等效 batch = 4(每卡) × 3(卡) × 3 = 36**（≈设计口径 32）：类别不均衡下大 batch 梯度更稳、更易覆盖长尾样本；若改单卡跑需恢复 8（4×1×8=32） |
| `warmup_steps` | 0 | **150** | ≈5.4% × 2,793 步（val_size 0.05 后训练数据 33,512 条 ÷ 等效 batch 36 = 931 步/epoch × 3 epoch）；cosine + 1e-4 温和起步（warmup 0~10% 均可，取整 150 便于记忆） |
| `logging_steps` | 5 | **10** | 纯观测密度，非必要 |
| `image_max_pixels` | 768*768 | **750\*1101** | 原图 750×1101 = 825,750 像素，设 750\*1101 即**完全不压缩**（smart_resize 对齐 28 倍数后实际输入 756×1092，面积保留 99.98%，视觉 token 1,053）；默认 768²（589,824）会被压缩到约 71% 细节、512² 纹理尽失——细粒度属性（面料/袖长/领型）依赖分辨率，不压缩收益最大 |
| `val_size` | 0 | **0.05** | 通过 `val_size` 从训练集内部随机切 5%（≈1,764 条，按样本，attr_json 一图一样本≈按图切）画 val loss 曲线，与手动 val/test 零重叠、不污染评测；注意训练中 eval loss 是**语言建模口径 ≠ 属性准确率**，仅作过拟合监控信号，**最终结论仍以 `scripts/eval_attr.py` 在 test 上的属性级指标为准** |

## 二、保持默认的关键参数（及原因）

| 参数 | 值 | 为什么不改 |
|---|---|---|
| `save_steps` | 100 | 保持默认：配置里 `eval_steps` 与 `save_steps` 同为 100，val loss 曲线点数 = 总步数/save_steps；100 步一 eval → 2,793 步约 28 个点，够看清过拟合趋势；代价是全程 28 次 val eval（约多花 30~60 分钟）与 28 个 checkpoint（LoRA adapter 仅几十 MB，磁盘无压力）；若嫌 eval 开销大可改 200（14 个点） |
| `num_train_epochs` | 3.0 | 35.3k 模式固定任务 2~3 epoch 充分，3 保证长尾类别轮巡完整 |
| `cutoff_len` | 2048 | 预算 ≈ 视觉 1,053 + 指令 367 + 输出 119 + 模板 ≈ 1,640，宽裕 |
| `freeze_vision_tower` / `freeze_multi_modal_projector` | true | 4 万图量级不大，冻结防过拟合 + 省显存；解冻留给消融 |
| `enable_thinking` | true | **不必改**（草稿曾建议改 false）：`qwen3_vl_nothink` 模板本身不插入 think 标记，源码证实 true/false 无差异 |
| `freeze_trainable_layers` | 2 | 保持默认（未改动）：该参数仅 freeze 微调生效，LoRA 下无意义，改不改都不影响训练 |
| `quantization_bit` | none | 48G 够 bf16 全精度，量化损失细粒度视觉精度 |
| 其余（cosine、adamw、max_grad_norm 1.0、seed 42、packing false、ds none） | 默认 | 无偏离理由 |

## 三、注意事项

1. **运行方式**：CLI 提交训练时 LLaMA-Factory 检测到 3 卡**自动走 DDP**（无需配置）；本配置按 3 卡设计（等效 batch 36）。若临时想单卡跑（如小步验证），用 `CUDA_VISIBLE_DEVICES=0` 限制单卡并把 `gradient_accumulation_steps` 恢复为 8（4×1×8=32）；
2. **显存**：不压缩后视觉 token 1,053（比 768² 的 726 多约 45%），batch 4 每卡在无梯度检查点下激活更高，**先 `max_samples: 500` 小步验证显存峰值**；OOM 依次尝试：降 batch 2 + accum 5（等效 30）→ 开 `gradient_checkpointing` → 最后才降 `image_max_pixels` 到 512²（需同步改 eval 配置）；
3. **训练-推理一致**：评测/部署的图像分辨率、schema prompt、解码参数与训练完全一致（`image_max_pixels` 同步 825,750 = 不压缩）；
4. **环境**：`lf` 环境需 `pip install omegaconf`（LLaMA-Factory 0.9.x 解析配置必需）；
5. **小步验证**：先 `max_samples: 500` 跑 1~2 步确认 loss 下降、显存稳定，再全量；
6. **过拟合兜底**：训练中 val loss 曲线 epoch 2 后回升 → `lora_dropout` 提到 0.1 或 epoch 降为 2；显存不足 → 先开 `gradient_checkpointing`，最后才降 `image_max_pixels` 到 512²（同步改 eval）。

> 消融入口（改配置即可）：simple 指令对照 / 数据量 5k / 解冻视觉塔 / 多任务 +caption / rank 8 / lr 5e-5 / 分辨率 512²。
