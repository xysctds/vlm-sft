## 1. 目录组织

```
data/
├── data_origin/                    # 原始数据（下载后原样存放，只读）
│   ├── DeepFashion/                # 经典 DeepFashion（Anno_coarse/Anno_fine/Eval/Img，暂未处理）
│   └── DeepFashion-MultiModal/     # DeepFashion-MultiModal（Text2Human, SIGGRAPH 2022）
│       ├── googledrive/            # 官方下载压缩包：images/labels/segm/densepose/keypoints.zip + captions.json
│       └── assets/  LICENSE  README.md   # 官方仓库附带文件
└── data_convert/                   # 解压/转换后的数据（LLaMA-Factory 直接消费）
    └── deepfashion_multi/          # DeepFashion-MultiModal 解压 + 转换产物
        ├── images/                 # 44,096 张原图（由 images.zip 解压）
        ├── labels/                 # 属性标注：shape/shape_anno_all.txt + texture/{fabric,pattern}_ann.txt
        ├── captions.json
        ├── segm/  densepose/  keypoints/  # 可选解压（VLM 微调用不到）
        ├── retrieval/              # 检索索引（index_meta.json + index_vectors.npy）
        ├── deepfashion_{attr_json,attr_json_simple,caption,attr_qa}_{train,val,test}.jsonl  # 转换产物
        ├── deepfashion_attr_json_fewshot_val.jsonl  # 评测用 few-shot 样例
        └── dataset_info.json       # LLaMA-Factory 数据集注册表
```

**约定**：`data_origin` 只放下载的原始版本，`data_convert` 放转换处理后的数据。转换脚本的输入输出默认路径都指向这两个目录，可直接无参运行。

## 2. 获取与解压

本项目当前唯一处理的数据集是 DeepFashion-MultiModal，官方仓库为 [yumingj/DeepFashion-MultiModal](https://github.com/yumingj/DeepFashion-MultiModal)（Text2Human, SIGGRAPH 2022）。从官方仓库的 Google Drive 下载下列压缩包（与本任务无关的 `segm` / `densepose` / `keypoints` 可不下载），放到 `data/data_origin/DeepFashion-MultiModal/googledrive/`：

| 文件 | 内容 |
|---|---|
| `images.zip` | 44,096 张 750×1101 JPEG 服饰全身图 |
| `labels.zip` | `shape_anno_all.txt`（12 个形状属性）+ `fabric_ann.txt` / `pattern_ann.txt`（上/下/外装各 3 列） |
| `captions.json` | 42,544 条图像 → 自然语言描述 |
| `segm.zip` / `densepose.zip` / `keypoints.zip` | 人体解析 / DensePose / 关键点（**VLM SFT 用不到**） |

把它们解压到 `data/data_convert/deepfashion_multi/`：

```bash
cd data/data_convert
mkdir -p deepfashion_multi
unzip -q ../data_origin/DeepFashion-MultiModal/googledrive/images.zip  -d deepfashion_multi
unzip -q ../data_origin/DeepFashion-MultiModal/googledrive/labels.zip  -d deepfashion_multi
unzip -q ../data_origin/DeepFashion-MultiModal/googledrive/segm.zip    -d deepfashion_multi   # 可选
unzip -q ../data_origin/DeepFashion-MultiModal/googledrive/densepose.zip -d deepfashion_multi  # 可选
unzip -q ../data_origin/DeepFashion-MultiModal/googledrive/keypoints.zip -d deepfashion_multi  # 可选
cp ../data_origin/DeepFashion-MultiModal/googledrive/captions.json deepfashion_multi/
```

若磁盘紧张，`segm/densepose/keypoints` 可跳过，VLM 微调只需要 `images/`、`labels/`、`captions.json`。

## 3. 转换为训练数据

把解压后的数据转换成 LLaMA-Factory 可消费的 sharegpt JSONL，由单个脚本 `scripts/data_convert_deepfashion_multi.py` 完成：输入 `data/data_convert/deepfashion_multi`，输出到同目录。

**运行**：

```bash
python scripts/data_convert_deepfashion_multi.py \
    --data data/data_convert/deepfashion_multi
```

**处理规则**：

- 属性清洗：脚本把 `NA` 和 `hidden` 都视为无效值剔除（`NA_VALUES = {"NA", "hidden"}`），属性任务只保留可见（非 NA）属性，因此每张图实际输出约 10~16 个键；原始 `captions.json` 中的 7 条空描述也已自动清洗。
- 任务模板：`attr_qa` 任务使用官方问句模板（如 `sleeve_length` → "What is the sleeve length of the clothing?"），见脚本 `SHAPE_QUESTIONS` / `PART_QUESTIONS`。
- 划分职责：train 用于训练；val 供训练监控与调参参考；test 只在最终评测时使用，全程只碰一次。训练中的 loss 曲线通过 `val_size: 0.05`（从训练集内部切 5%）实现，与手动 val/test 零重叠；正式评测统一走 `scripts/eval_attr.py` 在 test 集上出属性级指标。
- 可选参数：`--tasks`（指定任务子集）、`--val-ratio`、`--test-ratio`、`--seed`。

产出的 JSONL 均为 LLaMA-Factory 多模态 sharegpt 格式（样本结构见 §5），并在输出目录生成 `dataset_info.json` 注册表（见 4）。转换产出四类任务的数据集——`deepfashion_attr_json_*`、`deepfashion_attr_json_simple_*`、`deepfashion_caption_*`、`deepfashion_attr_qa_*`，各自含 train / val / test 三份。

四类任务的输入输出、各集条数与划分见主文档 §3.3；属性定义与指令原文见主文档 §3.2 / §3.4。

## 4. 接入 LLaMA-Factory

每个输出目录自带 `dataset_info.json`，LLaMA-Factory 从 `dataset_dir/dataset_info.json` 读取注册表；条目格式为 `formatting: sharegpt` + `columns: {messages, images}` + `tags`。接入时有四点需要注意：

1. 图片路径是相对 `dataset_dir` 的（LLaMA-Factory 的 `media_dir` 默认等于 `dataset_dir`，会自动拼接；`images/` 里没有的文件会报错，抽检确认）。
2. 训练时只需在 YAML 里把 `dataset_dir` 指向对应转换目录，`dataset` / `eval_dataset` 填注册表中的名字（如 `deepfashion_attr_json_train`）。
3. `<image>` 占位符由 LLaMA-Factory 自动替换为视觉 token，数量需与 `images` 列表长度一致（本转换均为 1 张图）。
4. 注册表与样本的字段必须对得上，否则会静默丢样本；样本实际结构见 §5。

训练配置只需三行：

```yaml
dataset_dir: data/data_convert/deepfashion_multi
dataset: deepfashion_attr_json_train    # 主线（schema 版）；对照用 deepfashion_attr_json_simple_train；辅助用 deepfashion_caption_train
template: qwen3_vl_nothink
```

完整训练与导出配置见 `experiments/qwen3vl8b/main/config/qwen3vl8b_dfattr_train_cli.yaml` 和同目录下的 `qwen3vl8b_dfattr_export_cli.yaml`（均为扁平 CLI 格式，分别用 `llamafactory-cli train` / `llamafactory-cli export` 运行）。

## 5. 样本格式

转换产物是 sharegpt 多模态格式（与 `llamafactory/data/mllm_demo.json` 同构），每条样本由 `messages`（user/assistant 对）与 `images`（相对 `dataset_dir` 的图片路径）组成。下面是 attr_json 主线样本的完整内容，为便于阅读按 JSON 缩进展开，`content` 里的换行直接显示成多行：

```json
{
  "messages": [
    {
      "role": "user",
      "content": "<image>Extract the clothing attributes visible in this image and output a JSON object.

Allowed keys and values:
- sleeve_length: sleeveless, short-sleeve, medium-sleeve, long-sleeve, not long-sleeve
- lower_clothing_length: three-point, medium short, three-quarter, long
- socks: no, socks, leggings
- hat: no, yes
- glasses: no, eyeglasses, sunglasses, glasses in hand or on clothes
- neckwear: no, yes
- wrist_wearing: no, yes
- ring: no, yes
- waist_accessories: no, belt, clothing at waist
- neckline: V-shape, square, round, standing, lapel, suspenders
- outer_clothing_is_cardigan: yes, no
- upper_clothing_covering_navel: no, yes
- upper_fabric: denim, cotton, leather, furry, knitted, chiffon, other
- upper_pattern: floral, graphic, striped, pure color, lattice, other, color block
- lower_fabric: denim, cotton, leather, furry, knitted, chiffon, other
- lower_pattern: floral, graphic, striped, pure color, lattice, other, color block
- outer_fabric: denim, cotton, leather, furry, knitted, chiffon, other
- outer_pattern: floral, graphic, striped, pure color, lattice, other, color block

Rules:
- Include only keys whose attribute is clearly visible in the image.
- Use only the allowed values listed above.
- Output the JSON object only, without any extra text or explanation."
    },
    {
      "role": "assistant",
      "content": {
        "sleeve_length": "short-sleeve",
        "lower_clothing_length": "three-point",
        "socks": "no",
        "hat": "no",
        "glasses": "sunglasses",
        "neckwear": "no",
        "wrist_wearing": "no",
        "ring": "yes",
        "waist_accessories": "no",
        "neckline": "round",
        "outer_clothing_is_cardigan": "no",
        "upper_clothing_covering_navel": "no",
        "upper_fabric": "cotton",
        "lower_fabric": "cotton",
        "upper_pattern": "pure color",
        "lower_pattern": "lattice"
      }
    }
  ],
  "images": ["images/WOMEN-Shorts-id_00005838-04_4_full.jpg"]
}
```

**三点约定**：

- 实际文件是 JSONL：每条样本压成一行，两个 `content` 在文件里都是字符串。上面为了可读做了两种展开——user 的换行写成 `\n`（显示时还原成多行），assistant 的内部 JSON 引号写成 `\"`（显示时还原成对象）。
  - user 在文件里形如：`"content": "<image>Extract ...JSON object.\n\nAllowed keys and values:\n- sleeve_length: ..."`
  - assistant 在文件里形如：`"content": "{\"sleeve_length\": \"short-sleeve\", ...}"`
- `<image>` 只出现一次，且与 `images` 列表等长（本转换均为 1 张图）。
- user 的 `content` 就是主文档 §3.4 的完整指令；assistant 的 `content` 是该样本的 16 个可见属性，不带 Markdown 围栏、不带解释，与指令里的三条 Rules 对应。
