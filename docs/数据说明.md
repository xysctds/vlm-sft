# 数据说明

> 本文档说明当前仓库中视觉数据集的**目录组织**、**原始格式**、**转换脚本用法**，以及转换后的数据如何接入 **LLaMA-Factory** 做多模态 SFT 微调。

---

## 1. 目录组织

```
data/
├── data_origin/                  # 原始数据（下载后原样存放，只读）
│   ├── ChartQA/                  #   ChartQA 数据集（HF datasets parquet 分片）
│   │   └── data/*.parquet        #     train-0000x-of-00003 / val / test 共 5 个分片
│   ├── DeepFashion/              #   经典 DeepFashion 数据集（Anno_coarse/Anno_fine/Eval/Img，暂未处理）
│   └── DeepFashion-MultiModal/   #   DeepFashion-MultiModal（Text2Human, SIGGRAPH 2022）
│       ├── googledrive/          #     官方下载压缩包：images.zip / labels.zip / segm.zip / densepose.zip / keypoints.zip + captions.json
│       ├── assets/ LICENSE/ README.md
└── data_convert/                 # 转换/解压后的数据（LLaMA-Factory 直接消费）
    ├── chartqa/                  #   ChartQA 转换产物
    │   ├── chartqa_{train,val,test}.jsonl
    │   ├── images/               #   去重后的图表 PNG（按内容 md5 命名）
    │   └── dataset_info.json
    └── deepfashion_multi/        #   DeepFashion-MultiModal 解压 + 转换产物
        ├── images/               #   44,096 张原图（由 images.zip 解压）
        ├── labels/  captions.json  segm/  densepose/  keypoints/
        ├── deepfashion_{caption,attr_qa,attr_json}_{train,val}.jsonl
        └── dataset_info.json
```

约定：**`data_origin` 只放下载的原始版本，`data_convert` 放转换处理后的数据**。转换脚本的输入输出默认路径都指向这两个目录，可直接无参运行。

## 2. 转换脚本总览

| 脚本 | 输入（原始） | 输出（转换后） | 产物 |
|---|---|---|---|
| `scripts/data_convert_chartqa.py` | `data/data_origin/ChartQA/data` | `data/data_convert/chartqa` | 3 个 split 的 sharegpt JSONL + 去重图片 |
| `scripts/data_convert_deepfashion_multi.py` | `data/data_convert/deepfashion_multi`（解压后的数据集） | 同目录 | 3 种任务 × train/val 的 sharegpt JSONL |

两个脚本产出的 JSONL 均为 LLaMA-Factory 多模态 **sharegpt** 格式，并在输出目录生成 `dataset_info.json` 注册表（详见第 5 节）。

## 3. ChartQA

### 3.1 原始格式

HF `datasets` 仓库的本地 parquet 分片（`data/data_origin/ChartQA/data/`），schema：

| 列 | 类型 | 含义 |
|---|---|---|
| `image` | `struct<bytes: binary, path: string>` | HF Image feature 序列化，图片字节内嵌在 parquet（PNG） |
| `query` | `string` | 图表问题 |
| `label` | `list<string>` | 标准答案（恒为 1 个元素，短答案） |
| `human_or_machine` | `int64` | 0=人工问题，1=机器生成问题 |

数据量：train 28,299 / val 1,920 / test 2,500 条。

### 3.2 转换

```bash
conda activate lf
python scripts/data_convert_chartqa.py \
    --src data/data_origin/ChartQA/data \
    --out data/data_convert/chartqa
```

要点：
- 图片从 parquet 字节提取为 PNG 文件，按 **md5 去重**（同一图表多问题只存一张）。
- 每条记录：`user: <image><query>`，`assistant: <label[0]>`。
- 可选参数 `--dataset-name-prefix` 控制注册表中的数据集名前缀（默认 `chartqa`）。

### 3.3 训练配置

```yaml
dataset_dir: data/data_convert/chartqa
dataset: chartqa_train
eval_dataset: chartqa_val
template: qwen3_vl_nothink   # Qwen2.5-VL 用 qwen2_5_vl
```

## 4. DeepFashion-MultiModal

### 4.1 原始格式

官方 GitHub（[yumingj/DeepFashion-MultiModal](https://github.com/yumingj/DeepFashion-MultiModal)）下载的压缩包位于 `data/data_origin/DeepFashion-MultiModal/googledrive/`：

| 文件 | 内容 |
|---|---|
| `images.zip` | 44,096 张 750×1101 JPEG 服饰全身图 |
| `labels.zip` | `shape_anno_all.txt`（12 个形状属性）+ `fabric_ann.txt` / `pattern_ann.txt`（上/下/外装各 3 列） |
| `captions.json` | 42,544 条图像 → 自然语言描述 |
| `segm.zip` / `densepose.zip` / `keypoints.zip` | 人体解析 / DensePose / 关键点（**VLM SFT 用不到**） |

属性 id → 语义值映射见官方 README，脚本已内置（如袖长 `0=无袖 1=短袖 2=中袖 3=长袖 4=非长袖 5=NA`；面料 `0=牛仔 1=棉 2=皮 3=毛 4=针织 5=雪纺 6=其他 7=NA`；图案 `0=碎花 1=图形 2=条纹 3=纯色 4=格纹 5=其他 6=色块 7=NA`）。完整的 18 维属性键/取值英中对照见**「附录：属性对照表（英中）」**（本文档唯一权威属性来源，`scripts/data_convert_deepfashion_multi.py` 内嵌的 `SHAPE_ATTRS`/`FABRIC_VALS`/`PATTERN_VALS` 与此一致）。

### 4.2 准备（解压）

先把 `googledrive/` 下的压缩包解压到 `data/data_convert/deepfashion_multi/`：

```bash
cd data/data_convert
mkdir -p deepfashion_multi
unzip -q ../data_origin/DeepFashion-MultiModal/googledrive/images.zip  -d deepfashion_multi
unzip -q ../data_origin/DeepFashion-MultiModal/googledrive/labels.zip  -d deepfashion_multi
unzip -q ../data_origin/DeepFashion-MultiModal/googledrive/segm.zip    -d deepfashion_multi   # 可选
unzip -q ../data_origin/DeepFashion-MultiModal/googledrive/densepose.zip -d deepfashion_multi  # 可选
unzip -q ../data_origin/DeepFashion-MultiModal/googledrive/keypoints.zip -d deepfashion_multi  # 可选
cp ../data_origin/DeepFashion-MultiModal/googledrive/captions.json deepfashion_multi/
```

> 若磁盘紧张，`segm/densepose/keypoints` 可跳过，VLM 微调只需要 `images/`、`labels/`、`captions.json`。

### 4.3 转换

```bash
python scripts/data_convert_deepfashion_multi.py \
    --data data/data_convert/deepfashion_multi
```

按**图片粒度**做 train/val/test 划分（默认 80/10/10，seed=42，三侧图片两两零重叠；**test 仅用于最终评测**），产出 4 种任务：

| 任务 | 数据量 (train/val/test) | 示例 | 定位 |
|---|---|---|---|
| `deepfashion_attr_json_*` | 35,276 / 4,410 / 4,410 | `<image>Extract the clothing attributes visible in this image and output a JSON object.`（**schema 枚举指令**：列出全部 18 个键与取值，规则"只输出可见属性"）→ `{"sleeve_length": "short-sleeve", ...}` | **主线任务** |
| `deepfashion_attr_json_simple_*` | 35,276 / 4,410 / 4,410 | `<image>Extract the clothing attributes visible in this image and output them as JSON.` → 同上 | 对照实验（朴素指令） |
| `deepfashion_caption_*` | 34,006 / 4,258 / 4,273 | `<image>Describe the clothing and the person in this image.` → 官方描述 | 辅助（多任务消融） |
| `deepfashion_attr_qa_*` | 451,744 / 56,860 / 56,943 | `<image>What is the sleeve length of the clothing?` → `short-sleeve` | **弃用**（模板重复易过拟合，保留不用于主线） |

说明：
- 属性任务只保留**可见（非 NA）**属性；`hidden` 也视为无效值剔除；原始 `captions.json` 中的 7 条空描述已自动清洗。
- `attr_json`（schema 版）输出结构化 JSON，与项目主线「图像 → 结构化输出」最契合；`simple` 版用于量化 schema 指令 vs 朴素指令的效果差异。
- 划分职责：train 训练；val 供训练监控/调参参考；test 只在最终评测时使用，全程只碰一次。训练中 loss 曲线通过 `val_size: 0.05`（从训练集内部切 5%）实现，与手动 val/test 零重叠；**正式评测统一走 `scripts/eval_attr.py` 在 test 集上出属性级指标**。
- 可选参数：`--tasks`（指定任务子集）、`--val-ratio`、`--test-ratio`、`--seed`。

### 4.4 训练配置

```yaml
dataset_dir: data/data_convert/deepfashion_multi
dataset: deepfashion_attr_json_train    # 主线（schema 版）；对照用 deepfashion_attr_json_simple_train；辅助用 deepfashion_caption_train
template: qwen3_vl_nothink
```

完整训练/导出配置见 `llamafactory/config/qwen3vl8b_dfattr_train_cli.yaml`（扁平 CLI 格式，`llamafactory-cli train` 运行）与 `qwen3vl8b_dfattr_export_cli.yaml`（扁平 CLI 格式，终端运行）。

## 5. LLaMA-Factory 接入原理

转换脚本产出的 JSONL 是 sharegpt 多模态格式（与 `llamafactory/data/mllm_demo.json` 同构）：

```json
{
  "messages": [
    {"role": "user", "content": "<image>What is the sleeve length of the clothing?"},
    {"role": "assistant", "content": "short-sleeve"}
  ],
  "images": ["images/xxx.jpg"]
}
```

接入要点：
1. **图片路径**是相对 `dataset_dir` 的（LLaMA-Factory 的 `media_dir` 默认等于 `dataset_dir`，会自动拼接；`images/` 里没有的文件会报错，抽检确认）。
2. 每个输出目录自带 `dataset_info.json`，LLaMA-Factory 从 `dataset_dir/dataset_info.json` 读取注册表；条目格式为 `formatting: sharegpt` + `columns: {messages, images}` + `tags`。
3. 训练时只需在 YAML 里把 `dataset_dir` 指向对应转换目录，`dataset`/`eval_dataset` 填注册表中的名字（如 `chartqa_train`、`deepfashion_attr_json_train`）。
4. `<image>` 占位符由 LLaMA-Factory 自动替换为视觉 token，数量需与 `images` 列表长度一致（本转换均为 1 张图）。

| 属性键（英文） | 属性键（中文） | 取值（官方英文） | 取值（中文） |

| `outer_pattern` | 外衣图案 | | |

### A.4 补充说明

- `NA` 表示该属性在图中不可见（如没穿外衣时 `outer_*` 为 NA）；`waist_accessories` 的 `hidden` 表示腰部被遮挡、无法判断。
- 转换脚本将 **`NA` 和 `hidden` 均视为无效值剔除**（`NA_VALUES = {"NA", "hidden"}`），训练/评测只针对可见属性，因此每张图实际输出的键约 10~16 个。
- 每个属性键对应一个官方问句模板（如 `sleeve_length` → "What is the sleeve length of the clothing?"），见脚本 `SHAPE_QUESTIONS` / `PART_QUESTIONS`。
