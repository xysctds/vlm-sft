## 1. 目录组织

```
data/
├── data_origin/                    # 原始数据（下载后原样存放，只读）
│   ├── DeepFashion/                # 经典 DeepFashion（Anno_coarse/Anno_fine/Eval/Img，暂未处理）
│   └── DeepFashion-MultiModal/     # DeepFashion-MultiModal（Text2Human, SIGGRAPH 2022）
│       ├── googledrive/            # 官方下载压缩包：images/labels/segm/densepose/keypoints.zip + captions.json
│       └── assets/  LICENSE  README.md   # 官方仓库附带文件
└── data_convert/                   # 解压/转换后的数据（LLaMA-Factory 直接消费）
    └── deepfashion_multi/          # DeepFashion-MultiModal 解压 + 转换产物
        ├── images/                 # 44,096 张原图（由 images.zip 解压）
        ├── labels/                 # 属性标注：shape/shape_anno_all.txt + texture/{fabric,pattern}_ann.txt
        ├── captions.json
        ├── segm/  densepose/  keypoints/  # 可选解压（VLM 微调用不到）
        ├── retrieval/              # 检索索引（index_meta.json + index_vectors.npy）
        ├── deepfashion_{attr_json,attr_json_simple,caption,attr_qa}_{train,val,test}.jsonl  # 转换产物
        ├── deepfashion_attr_json_fewshot_val.jsonl  # 评测用 few-shot 样例
        └── dataset_info.json       # LLaMA-Factory 数据集注册表
```

**约定**：`data_origin` 只放下载的原始版本，`data_convert` 放转换处理后的数据。转换脚本的输入输出默认路径都指向这两个目录，可直接无参运行。

## 2. 数据集：DeepFashion-MultiModal

本项目当前唯一处理的数据集。官方仓库为 [yumingj/DeepFashion-MultiModal](https://github.com/yumingj/DeepFashion-MultiModal)（Text2Human, SIGGRAPH 2022）。本节依次介绍原始格式、解压准备、属性定义。

### 2.1 原始格式

官方下载的压缩包位于 `data/data_origin/DeepFashion-MultiModal/googledrive/`：

| 文件 | 内容 |
|---|---|
| `images.zip` | 44,096 张 750×1101 JPEG 服饰全身图 |
| `labels.zip` | `shape_anno_all.txt`（12 个形状属性）+ `fabric_ann.txt` / `pattern_ann.txt`（上/下/外装各 3 列） |
| `captions.json` | 42,544 条图像 → 自然语言描述 |
| `segm.zip` / `densepose.zip` / `keypoints.zip` | 人体解析 / DensePose / 关键点（**VLM SFT 用不到**） |

### 2.2 准备（解压）

先把 `googledrive/` 下的压缩包解压到 `data/data_convert/deepfashion_multi/`：

```bash
cd data/data_convert
mkdir -p deepfashion_multi
unzip -q ../data_origin/DeepFashion-MultiModal/googledrive/images.zip  -d deepfashion_multi
unzip -q ../data_origin/DeepFashion-MultiModal/googledrive/labels.zip  -d deepfashion_multi
unzip -q ../data_origin/DeepFashion-MultiModal/googledrive/segm.zip    -d deepfashion_multi   # 可选
unzip -q ../data_origin/DeepFashion-MultiModal/googledrive/densepose.zip -d deepfashion_multi  # 可选
unzip -q ../data_origin/DeepFashion-MultiModal/googledrive/keypoints.zip -d deepfashion_multi  # 可选
cp ../data_origin/DeepFashion-MultiModal/googledrive/captions.json deepfashion_multi/
```

> 若磁盘紧张，`segm/densepose/keypoints` 可跳过，VLM 微调只需要 `images/`、`labels/`、`captions.json`。

### 2.3 属性定义（英中权威对照）

> **来源与权威性**：属性定义取自官方 README（https://github.com/yumingj/DeepFashion-MultiModal），并内嵌于 `scripts/data_convert_deepfashion_multi.py`（`SHAPE_ATTRS` / `FABRIC_VALS` / `PATTERN_VALS`）。本节为**权威来源**，主文档 `docs/DeepFashion技术方案与实验报告.md` 与 `docs/检索推荐说明.md` 中的内嵌副本以本节为准。
>
> **属性体系**：共 **18 维属性 = 12 个形状属性 + 3 个部位（上装/下装/外装）× 面料 + 3 个部位 × 图案**。

| 分组 | 属性键（英文） | 属性键（中文） | 取值（官方英文 / 中文） |
|---|---|---|---|
| 形状 | `sleeve_length` | 袖长 | sleeveless / short-sleeve / medium-sleeve / long-sleeve / not long-sleeve / NA<br>无袖 / 短袖 / 中袖 / 长袖 / 非长袖 / 不可见 |
| | `lower_clothing_length` | 下装长度 | three-point / medium short / three-quarter / long / NA<br>三分长度（短款）/ 中短 / 七分 / 长 / 不可见 |
| | `socks` | 袜子 | no / socks / leggings / NA<br>无 / 袜子 / 打底裤（紧身裤）/ 不可见 |
| | `hat` | 帽子 | no / yes / NA<br>无 / 有 / 不可见 |
| | `glasses` | 眼镜 | no / eyeglasses / sunglasses / glasses in hand or on clothes / NA<br>无 / 框架眼镜 / 太阳镜 / 拿在手中或挂在衣服上 / 不可见 |
| | `neckwear` | 颈饰（围巾/项链等） | no / yes / NA<br>无 / 有 / 不可见 |
| | `wrist_wearing` | 手腕佩戴物 | no / yes / NA<br>无 / 有 / 不可见 |
| | `ring` | 戒指 | no / yes / NA<br>无 / 有 / 不可见 |
| | `waist_accessories` | 腰部配饰 | no / belt / clothing at waist / hidden / NA<br>无 / 腰带 / 系在腰间的衣物 / 被遮挡 / 不可见 |
| | `neckline` | 领型 | V-shape / square / round / standing / lapel / suspenders / NA<br>V 领 / 方领 / 圆领 / 立领 / 翻领 / 背带（吊带）/ 不可见 |
| | `outer_clothing_is_cardigan` | 外衣是否为开衫 | yes / no / NA<br>是 / 否 / 不可见 |
| | `upper_clothing_covering_navel` | 上衣是否遮住肚脐 | no / yes / NA<br>否（露脐）/ 是 / 不可见 |
| 面料 | `{upper,lower,outer}_fabric` | 上衣 / 下装 / 外衣面料 | denim / cotton / leather / furry / knitted / chiffon / other / NA<br>牛仔 / 棉 / 皮革 / 毛绒 / 针织 / 雪纺 / 其他 / 不可见 |
| 图案 | `{upper,lower,outer}_pattern` | 上衣 / 下装 / 外衣图案 | floral / graphic / striped / pure color / lattice / other / color block / NA<br>碎花 / 图形 / 条纹 / 纯色 / 格纹 / 其他 / 色块 / 不可见 |

**来源文件**：形状属性（12 个）来自 `labels/shape/shape_anno_all.txt`；面料与图案属性分别对应 `{upper,lower,outer}_fabric` 与 `{upper,lower,outer}_pattern`（上装/下装/外装取值一致），来自 `labels/texture/fabric_ann.txt` 与 `labels/texture/pattern_ann.txt`（各三列）。

## 3. 数据转换

把解压后的数据转换成 LLaMA-Factory 可消费的 sharegpt JSONL，由单个脚本完成（见 3.1），产出多任务、多划分的训练数据（见 3.2），并详述主线任务的指令设计（见 3.3）。

### 3.1 转换脚本

转换由单个脚本 `scripts/data_convert_deepfashion_multi.py` 完成：输入 `data/data_convert/deepfashion_multi`（解压后的数据集），输出到同目录，产出 4 种任务 × train/val/test 的 sharegpt JSONL。

运行：

```bash
python scripts/data_convert_deepfashion_multi.py \
    --data data/data_convert/deepfashion_multi
```

脚本产出的 JSONL 均为 LLaMA-Factory 多模态 **sharegpt** 格式，并在输出目录生成 `dataset_info.json` 注册表（格式原理详见 4.1）。

**处理规则**：

- **属性清洗**：脚本将 **`NA` 和 `hidden` 均视为无效值剔除**（`NA_VALUES = {"NA", "hidden"}`），属性任务只保留**可见（非 NA）**属性，因此每张图实际输出的键约 10~16 个；原始 `captions.json` 中的 7 条空描述也已自动清洗。
- **任务模板**：`attr_qa` 任务使用官方问句模板（如 `sleeve_length` → "What is the sleeve length of the clothing?"），见脚本 `SHAPE_QUESTIONS` / `PART_QUESTIONS`。
- **划分职责**：train 用于训练；val 供训练监控/调参参考；test 只在最终评测时使用，全程只碰一次。训练中 loss 曲线通过 `val_size: 0.05`（从训练集内部切 5%）实现，与手动 val/test 零重叠；**正式评测统一走 `scripts/eval_attr.py` 在 test 集上出属性级指标**。
- **可选参数**：`--tasks`（指定任务子集）、`--val-ratio`、`--test-ratio`、`--seed`。

### 3.2 转换产物

脚本按**图片粒度**做 train/val/test 划分（默认 80/10/10，seed=42，三侧图片两两零重叠；**test 仅用于最终评测**），产出 4 种任务：

| 数据集（dataset_info.json 注册名） | train / val / test | 输入 → 输出 | 定位 |
|---|---|---|---|
| `deepfashion_attr_json_*` | 35,276 / 4,410 / 4,410 | 图 + **schema 枚举指令** → 完整属性 JSON | **主线任务** |
| `deepfashion_attr_json_simple_*` | 35,276 / 4,410 / 4,410 | 图 + 朴素一句话指令 → 完整属性 JSON | 对照实验 |
| `deepfashion_caption_*` | 34,006 / 4,258 / 4,273 | 图 → 自然语言描述 | 辅助（多任务组合暂不纳入主线） |
| `deepfashion_attr_qa_*` | 451,744 / 56,860 / 56,943 | 逐属性单问 → 单值 | 弃用（模板重复易过拟合，保留不用于主线） |

### 3.3 主线任务 `attr_json`

**为什么 attr_json 做主任务**：一次推理输出完整结构化属性，贴合真实电商抽取场景；输出为 JSON，与「图像 → 结构化输出」主线一致；评测可按属性键解构，严谨且细粒度。`simple` 版用于量化 schema 指令 vs 朴素指令的效果差异。

**schema 感知指令**（行业标准结构化输出的数据侧做法；`build_schema_prompt()` 由属性表自动生成，训练/评测共用完整原文）：

```
Extract the clothing attributes visible in this image and output a JSON object.

Allowed keys and values:
- sleeve_length: sleeveless, short-sleeve, medium-sleeve, long-sleeve, not long-sleeve
- lower_clothing_length: three-point, medium short, three-quarter, long
- socks: no, socks, leggings
- hat: no, yes
- glasses: no, eyeglasses, sunglasses, glasses in hand or on clothes
- neckwear: no, yes
- wrist_wearing: no, yes
- ring: no, yes
- waist_accessories: no, belt, clothing at waist
- neckline: V-shape, square, round, standing, lapel, suspenders
- outer_clothing_is_cardigan: yes, no
- upper_clothing_covering_navel: no, yes
- upper_fabric: denim, cotton, leather, furry, knitted, chiffon, other
- upper_pattern: floral, graphic, striped, pure color, lattice, other, color block
- lower_fabric: denim, cotton, leather, furry, knitted, chiffon, other
- lower_pattern: floral, graphic, striped, pure color, lattice, other, color block
- outer_fabric: denim, cotton, leather, furry, knitted, chiffon, other
- outer_pattern: floral, graphic, striped, pure color, lattice, other, color block

Rules:
- Include only keys whose attribute is clearly visible in the image.
- Use only the allowed values listed above.
- Output the JSON object only, without any extra text or explanation.
```

**指令结构**：

1. **任务句**：`Extract the clothing attributes visible in this image and output a JSON object.`
2. **Allowed keys and values**：枚举全部 18 个属性键及每键合法取值。
3. **Rules**：三条输出规则。

指令由官方属性表自动生成，键与取值顺序稳定，保证训练/评测/推理三端完全一致。朴素指令对照版（simple）：`Extract the clothing attributes visible in this image and output them as JSON.` 完整训练样本示例见 4.1。

## 4. LLaMA-Factory 接入

### 4.1 格式原理

转换脚本产出的 JSONL 是 sharegpt 多模态格式（与 `llamafactory/data/mllm_demo.json` 同构），每条样本由 `messages`（user/assistant 对）与 `images`（相对 `dataset_dir` 的图片路径）组成。以 **attr_json 主线样本**为例（schema 指令 + 完整属性 JSON，`deepfashion_attr_json_*` 任务的实际样本）：

```json
{"messages": [{"role": "user", "content": "<image>Extract the clothing attributes visible in this image and output a JSON object.\n\nAllowed keys and values:\n- sleeve_length: sleeveless, short-sleeve, medium-sleeve, long-sleeve\n...\nRules:\n- Include only keys whose attribute is clearly visible in the image.\n- Use only the allowed values listed above.\n- Output the JSON object only, without any extra text or explanation."}, {"role": "assistant", "content": "{\"sleeve_length\": \"short-sleeve\", \"lower_clothing_length\": \"three-point\", \"socks\": \"no\", \"hat\": \"no\", \"glasses\": \"sunglasses\", \"neckwear\": \"no\", \"wrist_wearing\": \"no\", \"ring\": \"yes\", \"waist_accessories\": \"no\", \"neckline\": \"round\", \"outer_clothing_is_cardigan\": \"no\", \"upper_clothing_covering_navel\": \"no\", \"upper_fabric\": \"cotton\", \"lower_fabric\": \"cotton\", \"upper_pattern\": \"pure color\", \"lower_pattern\": \"lattice\"}"}], "images": ["images/WOMEN-Shorts-id_00005838-04_4_full.jpg"]}
```

接入要点：

1. **图片路径**是相对 `dataset_dir` 的（LLaMA-Factory 的 `media_dir` 默认等于 `dataset_dir`，会自动拼接；`images/` 里没有的文件会报错，抽检确认）。
2. 每个输出目录自带 `dataset_info.json`，LLaMA-Factory 从 `dataset_dir/dataset_info.json` 读取注册表；条目格式为 `formatting: sharegpt` + `columns: {messages, images}` + `tags`。
3. 训练时只需在 YAML 里把 `dataset_dir` 指向对应转换目录，`dataset`/`eval_dataset` 填注册表中的名字（如 `deepfashion_attr_json_train`）。
4. `<image>` 占位符由 LLaMA-Factory 自动替换为视觉 token，数量需与 `images` 列表长度一致（本转换均为 1 张图）。

### 4.2 训练配置

```yaml
dataset_dir: data/data_convert/deepfashion_multi
dataset: deepfashion_attr_json_train    # 主线（schema 版）；对照用 deepfashion_attr_json_simple_train；辅助用 deepfashion_caption_train
template: qwen3_vl_nothink
```

完整训练/导出配置见 `llamafactory/config/qwen3vl8b_dfattr_train_cli.yaml`（扁平 CLI 格式，`llamafactory-cli train` 运行）与 `qwen3vl8b_dfattr_export_cli.yaml`（扁平 CLI 格式，终端运行）。

## 5. 复现与注意事项

- **重新生成**：删掉 `data/data_convert/` 下对应产物后重跑脚本即可（脚本均幂等，图片按内容哈希不会重复写）。
- **DeepFashion（经典版）**：`data/data_origin/DeepFashion/` 尚未写转换脚本，如需处理再补。
