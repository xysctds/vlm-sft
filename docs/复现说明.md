# 复现说明

> 从零到部署的完整流程：前置条件 → 仓库结构 → 命令序列 → 路径约定。
> 参数含义、调参经验与部署细节分别在[数据说明](数据说明.md)、[训练说明](训练说明.md)、
> [部署说明](部署说明.md)与[检索说明](检索说明.md)。

## 1. 前置条件

| 项 | 要求 |
|---|---|
| 训练 GPU | 本机为 3×RTX 4090 48GB（batch 4 × 3 卡 DDP，实测每卡峰值 ≈30GB）；单卡 48GB 也可跑，把 `per_device_train_batch_size` 降 1~2、`gradient_accumulation_steps` 相应放大以保持等效 batch |
| 评测 / 推理 GPU | 单卡 24GB 起（8B 全 bf16 权重 ≈17.5GB） |
| 磁盘 | 数据 ≈16GB（图片 6.7GB + 转换产物）；基座权重 ≈33GB；训练产出 LoRA 适配器几十 MB、合并模型 ≈17GB |
| 训练时长 | 全量 3 epoch / 2,793 步，3×4090 上约 9.9h |
| 软件 | Python 3.11 + conda；依赖见仓库根 `requirements_lf_full.txt`（`pip freeze` 全量精确版） |

### 1.1 数据集

从上游仓库 [yumingj/DeepFashion-MultiModal](https://github.com/yumingj/DeepFashion-MultiModal) 下载
`images.zip` / `labels.zip` / `captions.json`（`segm` / `densepose` / `keypoints` 与本任务无关，可不下载），
放到 `data/data_origin/DeepFashion-MultiModal/googledrive/`，再按[数据说明 §2](数据说明.md#2-获取与解压)解压。

### 1.2 基座模型

下载 Qwen3-VL-8B-Instruct（HuggingFace 或 ModelScope 均可），放到 `models/Qwen3-VL-8B-Instruct`。
配置里的 `model_name_or_path` 都写这个相对路径，在仓库根运行即按本地目录加载。

### 1.3 建环境

```bash
conda create -n lf python=3.11 -y
conda activate lf
pip install -r requirements_lf_full.txt      # 全量精确版；只想装框架则 pip install "llamafactory[torch]"
export USE_MODELSCOPE_HUB=1                  # 走 ModelScope 时设置
```

部署另需一个 `vllm` 环境（克隆自 lf），见[部署说明 §2](部署说明.md#2-环境准备)。

## 2. 仓库结构

按流水线环节组织：

### 2.1 数据

| 路径 | 内容 |
|---|---|
| `scripts/data_convert_deepfashion_multi.py` | 数据转换（schema 主线 + simple 对照 + caption + attr_qa，属性表内嵌） |
| `scripts/check_data.py` | 数据质量四关卡（schema 健全 / 答案合法 / 防泄漏 / 分布统计） |
| `data/data_convert/deepfashion_multi/` | 转换产物（jsonl + `dataset_info.json` + `images/`） |
| [数据说明](数据说明.md) | 数据组织、原始格式、转换脚本、属性英中对照表 |

### 2.2 训练配置与权重

| 路径 | 内容 |
|---|---|
| `experiments/qwen3vl8b/main/config/`（及 `experiments/qwen3vl8b/ablation/config/`、`experiments/qwen3vl8b/ckpt_screen/config/`） | 训练/评测/导出配置（`main/`、`ablation/`、`ckpt_screen/` 子目录） |
| `experiments/qwen3vl8b/main/weights/`（`lora/`、`merged/`） | 模型权重与训练日志（LoRA adapter / merged；软链至 /disk16T1） |
| [训练说明](训练说明.md) | 训练超参与调参经验（改了什么、为什么改、什么保持默认） |

### 2.3 评测

| 路径 | 内容 |
|---|---|
| `scripts/convert_preds.py` | 把 llamafactory predict 输出（`generated_predictions.jsonl`）转为 `eval_attr.py stats` 可消费的预测文件 |
| `scripts/eval_attr.py` | 评测打分：`stats`（属性级 acc / macro-F1 / 分层 / McNemar）；预测生成走 llamafactory 管线（口径见[技术报告 §5.3](技术报告.md#53-评测口径一致性)与[§5.4](技术报告.md#54-评测执行)） |
| `experiments/qwen3vl8b/main/predictions/` | 评测生成预测（`generated_predictions.jsonl` 等，按实验分目录） |
| `experiments/qwen3vl8b/main/reports/`（及 `experiments/qwen3vl8b/ablation/reports/`、`experiments/qwen3vl8b/ckpt_screen/reports/`） | 评测汇总与评测日志（`preds_*.jsonl`、报告、数据统计、`eval_*.log`） |

### 2.4 检索与部署

| 路径 | 内容 |
|---|---|
| `scripts/build_retrieval_index.py` | 检索索引构建（官方标注聚合 + 视觉塔抽 embedding + 多卡分片） |
| `scripts/retrieval.py` | 相似款检索（视觉 + 属性混合加权；只加载视觉塔 + 缓存 + 预热） |
| `scripts/serve_demo.py` | vLLM demo 客户端（CLI） |
| `scripts/serve_gradio.py` | Gradio Web demo（模板切换 + prompt 手动编辑；含相似款检索 Gallery） |
| `scripts/start_vllm.sh` | vLLM 一键启动脚本（封装 CUDA_HOME / flashinfer 禁用等环境准备，单卡/多卡切换） |
| `scripts/start_web.sh` | Web demo 一键启动（vLLM + Gradio 全自动：GPU 分卡避让 / 健康检查） |
| [部署说明](部署说明.md) | 部署文档：环境准备、单卡/多卡启动、API 示例、踩坑记录 |
| [检索说明](检索说明.md) | 相似款检索说明（检索管线、工程纪律、落地产物） |

工程纪律：seed 固定（划分/训练/推理全链路）；每个实验一行 CSV + 元数据（模型、r、数据量、seed、指标）；requirements 精确版本；转换/评测脚本与报告发布 GitHub/HuggingFace（公开可复现）。

## 3. 端到端复现手册

从零到部署的一条流水线（脚本入口 + 主要产物）。每步可用 `bash -x` 看执行轨迹；`CUDA_VISIBLE_DEVICES` 可控制卡数。

### 3.1 环境

按 §1.3 建好环境后：

```bash
conda activate lf
export USE_MODELSCOPE_HUB=1
```

### 3.2 数据

把解压后的产物放到 `data/data_convert/deepfashion_multi/` 后无参运行（幂等）；数据组织与转换规则见[数据说明](数据说明.md)。

```bash
python scripts/data_convert_deepfashion_multi.py
python scripts/check_data.py                  # 四关卡，退出码 0 才继续
```

### 3.3 训练

单机多卡自动走 DDP，默认用全部可见 GPU；本机 3 卡，等效 batch = 4×3×3 = 36。超参与调参见[训练说明](训练说明.md)。

```bash
llamafactory-cli train experiments/qwen3vl8b/main/config/qwen3vl8b_dfattr_train_cli.yaml
# 单卡：CUDA_VISIBLE_DEVICES=0，并把 gradient_accumulation_steps 改为 9
```

### 3.4 消融

指令范式 × 数据量，结果见[技术报告 §6.1](技术报告.md#61-实验设计与对照矩阵)与[§6.3](技术报告.md#63-提升归因)。

```bash
# 训练：experiments/qwen3vl8b/ablation/config/*.yaml（schema/simple × 5k/20k/35k）
# 打分：同 3.5，产物在 experiments/qwen3vl8b/ablation/reports/report_ablation.md
```

### 3.5 评测

正式口径是 llamafactory 管线生成预测 + `eval_attr.py stats` 打分，原理与边界见[技术报告 §5.3](技术报告.md#53-评测口径一致性)。

```bash
# 开发阶段：val 集，可反复跑（两份配置除 eval_dataset 外一致）
llamafactory-cli train experiments/qwen3vl8b/main/config/qwen3vl8b_dfattr_eval_val_base.yaml   # 基座 0-shot
llamafactory-cli train experiments/qwen3vl8b/main/config/qwen3vl8b_dfattr_eval_val_lora.yaml   # LoRA 微调后
python scripts/convert_preds.py --preds experiments/qwen3vl8b/main/predictions/val_base/generated_predictions.jsonl \
    --data data/data_convert/deepfashion_multi/deepfashion_attr_json_val.jsonl --out experiments/qwen3vl8b/main/reports/preds_val_base.jsonl
python scripts/convert_preds.py --preds experiments/qwen3vl8b/main/predictions/val_lora/generated_predictions.jsonl \
    --data data/data_convert/deepfashion_multi/deepfashion_attr_json_val.jsonl --out experiments/qwen3vl8b/main/reports/preds_val_lora.jsonl
python scripts/eval_attr.py stats --base experiments/qwen3vl8b/main/reports/preds_val_base.jsonl \
    --lora experiments/qwen3vl8b/main/reports/preds_val_lora.jsonl --out experiments/qwen3vl8b/main/reports/report_val.md

# 最终报告：test 集，全程只碰一次（把 val 两份配置复制为 test 版，eval_dataset 改 deepfashion_attr_json_test）
# 其余环节产物：report_test.md / report_ckpt_screen.md / report_ckpt_confirm.md \
#               / report_resolution.md / report_category.md / report_supplement.md
```

### 3.6 检索

详见[技术报告 §8](技术报告.md#8-相似款检索)与[检索说明](检索说明.md)。

```bash
python scripts/build_retrieval_index.py       # 建检索索引（官方标注聚合 + 视觉塔抽 embedding）
```

### 3.7 部署

完整命令与环境准备见[技术报告 §9](技术报告.md#9-服务化部署)与[部署说明](部署说明.md)。

```bash
llamafactory-cli export experiments/qwen3vl8b/main/config/qwen3vl8b_dfattr_export_cli.yaml
conda activate vllm && export CUDA_HOME=/home/maotai/.conda/envs/vllm/lib/python3.11/site-packages/nvidia/cu13
VLLM_USE_FLASHINFER_SAMPLER=0 vllm serve experiments/qwen3vl8b/main/weights/merged/qwen3vl8b_dfattr_merged \
    --served-model-name deepfashion --port 8000 --max-model-len 32768
python scripts/serve_demo.py --image <path/to/test.jpg>      # CLI
python scripts/serve_gradio.py                                # Web → http://127.0.0.1:7860
```

> 各环节对应的产物落点均在上文命令注释标出；主报告产物集中在 `experiments/*/reports/`（val / test / ablation / ckpt / resolution / category / supplement）。

## 4. 环境与路径约定

项目用 conda 管理两套隔离环境：

| 环境名 | 用途 | 依赖 |
|---|---|---|
| `lf` | LLaMA-Factory 微调/评测（主线） | `requirements_lf_full.txt`（pip freeze 全量精确版） |
| `vllm` | 部署（克隆自 lf + `pip install vllm`，不污染训练环境） | 复现步骤见 `docs/部署说明.md` §2 |

> `vllm` 环境无独立依赖文件，按部署说明 §2 克隆 lf 后安装 vllm 0.27.1 + 升级 flashinfer 即可。

仓库内路径一律用相对路径（在仓库根运行即可），不含任何本机绝对路径：

| 项 | 约定 |
|---|---|
| 仓库内数据/产物路径 | 相对仓库根（`data/`、`experiments/qwen3vl8b/main/predictions/` 等），直接可用 |
| 基座模型 | 放到 `models/Qwen3-VL-8B-Instruct`（全部训练/评测/导出配置中 `model_name_or_path` 均写此相对路径，在仓库根运行即按本地目录加载） |

> **注意**：本仓库 llamafactory 的 CLI 用 `OmegaConf.to_container` 读配置，**不解析 `${oc.env:...}` 插值**（OmegaConf 2.3.x 的 `to_container` 默认不 resolve 插值，`${oc.env:LLM_MODEL_PATH, ...}` 会原样传给 HF 导致启动失败），因此配置中**直接写相对路径**、不要用插值写法；换机/发布时把模型软链到仓库 `models/Qwen3-VL-8B-Instruct` 即可（`grep -rn "model_name_or_path" experiments` 可找到全部位置）。
