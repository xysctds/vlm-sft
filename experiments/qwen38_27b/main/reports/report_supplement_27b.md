## 观察

- **指令依赖度**：LoRA 模型在 simple 指令下输出**退化为自由格式 JSON**（键名如 `top.type`/`clothing[].color`，不再是属性键名），按任务 schema 对齐后属性级准确率仅 0.4%（parse 率 99.7% 说明是合法 JSON 但结构不对齐）——**schema 指令是运行期必需**：业务部署必须携带 schema prompt，这也反向验证了训练期 schema 指令的价值；
- **指令依赖是固有的，不是微调造成的**：基座在 simple 指令下也只有 0.1%（schema 指令下 82.6%，parse 率 99.8%）——说明模型的结构化抽取能力本就完全依赖 prompt 里的 key/value 白名单，「推理期必须带 schema」在微调前后都成立，换基座或换训练指令都规避不了；
- **few-shot vs 微调**：基座 2-shot（80.8%）较 0-shot（82.6%）反而下降 1.7%pp，说明该基座已经足够强、示例提示不再带来收益（甚至略有干扰），且两者都不如微调，最好者**仍比微调（93.4%）低 10.8%pp**——用数据回答"为什么微调而不 few-shot"：few-shot 无法达到结构化抽取的业务可用水平，且每次推理多 2 个示例的输入开销。
